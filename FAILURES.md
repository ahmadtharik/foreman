# Failures

Log of what went wrong, as it happened. Material for the results write-up.

| Date | Stage | Ticket | What happened | Cause | What changed |
|---|---|---|---|---|---|
| 2026-11-18 | plan | #2 to #6 | Every ticket's definition of done says "tests, type check, lint", but the repo has no lint step. The builder noticed and said so in its PR. | The ticket template's default line names lint. The planner copied it instead of checking the project's real checks. | Fixed in #17: planner reads the project's real check commands; template names them. |
| 2026-11-18 | build | #2 | The PR description says "Closes #2", so merging will close the issue. Only the runner should change ticket state. | Builder skill does not forbid closing keywords. | Fixed in #17: builder skill requires `Refs #n` and forbids closing keywords. |
| 2026-11-22 | plan | #3 | Most test cases read "run the test file, case X", so the reviewer mostly confirms the builder's own tests pass. | The planner wrote test cases that point at tests the builder will write. | Fixed in #17: planner prefers cases the reviewer runs directly; self-check flags the rest. |
| 2026-11-22 | build | #6 | The builder pushed with the API token embedded in the git remote URL, which wrote the token into local git config. It noticed and removed it; a scan of the repo's git config, worktree configs and logs found no copy left. | No rule says how to push. The builder reached for the token because `gh` is absent. | Fixed in #17: builder pushes with existing credentials and reports blocked otherwise. |
| 2026-11-23 | plan | #25 | The plan gave both agents `Bash(curl *)`, which lets them reach any site. The handoff allows no network beyond package installs. | No rule limits network tools to the hosts a stage needs. | Narrowed by hand in #25 to `Bash(curl https://api.github.com/*)` before the build. Fixed in #35: planner scopes network tools to the host a stage needs. |
| 2026-11-24 | plan | #22 | Test case 4 says to remove "the path from case 1", but case 2 had already removed that worktree. The reviewer removed the one case 2 recreated and noted both readings pass. | Chained test cases share state, and the planner did not trace what each earlier case leaves behind. | Fixed in #35: planner makes each case state what it starts from. |
| 2026-11-26 | plan | #25 | Test case 2 writes `$!` to the lock file. Under Git Bash on Windows, `$!` is the MSYS pid, so the runner judged the holder dead, took the lock, and started a real runner loop that never exits. The builder skipped the case; the reviewer ran a corrected version (`/proc/$P/winpid`, a bogus token, a 30 second timeout). | The planner wrote a POSIX shell idiom without checking it on this machine, and the case starts the real runner if it misbehaves. | Reviewer brief replaced the case. Fixed in #35: planner runs commands on the reviewer's platform and forbids cases that can start a real runner or agent. |
| 2026-11-28 | build | #37 | The first two runner builds crashed with exit 1 within 2 seconds. The Claude Code login had reached its maximum lifetime and could not be renewed, so every `claude -p` failed. Ahmad signed in again and the third attempt ran. | A login refreshes itself only up to a limit. The runner has no check that the agent can start before it claims a ticket, so each crash counted as a failed run (2 of 3). | Open: check the agent login at runner start and before each claim, or use a long-lived `claude setup-token` token. |
| 2026-11-28 | build | #37 | The builder pushed its branch but could not open the PR, so it reported blocked and the runner moved #37 to Needs human. Its curl calls were refused: the allow rule `Bash(curl https://api.github.com/*)` matches only commands that start with that URL, and any `$FOREMAN_GITHUB_TOKEN` in the command is refused. | The skills never said how to write an API call, and the allow rule was not tested with the commands agents actually write. | Fixed in #41: build and review skills give one tested form, URL first, with the token passed by `--variable` and `--expand-header` instead of `$`. |
